# Установка гипервизора и ВМ стенда с нуля (2–3 ВМ, консольные)

Пошаговая инструкция для Windows-хоста: поставить VirtualBox, создать 2–3
**урезанные** ВМ Kali Linux (только консоль, без графики и без наборов
инструментов), настроить сеть так, чтобы всё оставалось изолированным и не
мешало тестированию. После шага 8 продолжай по [E2E_STAND.md](E2E_STAND.md)
(агенты, AR-скрипты), затем — сценарии из [E2E_SCENARIOS.md](E2E_SCENARIOS.md).

Состав будущего стенда:

| ВМ | Роль | Устанавливаем |
|---|---|---|
| **ВМ-1 `mail-prod-01`** | критичный сервер (цель атак) | sshd, nginx, rsyslog, wazuh-agent, AR-скрипты |
| **ВМ-2 `wks-finance-12`** | АРМ пользователя (источник атак) | wazuh-agent, AR-скрипты, (опц.) hydra |
| ВМ-3 `app-web-01` (опционально) | второй сервер | как ВМ-1 |

---

## Шаг 0. Проверка ресурсов

| Ресурс | 2 ВМ | 3 ВМ |
|---|---|---|
| ОЗУ (суммарно со стендом Docker) | **16 ГБ** комфортно, 8 ГБ — минимум | 16 ГБ (при 8 ГБ третий ВМ не поднимай) |
| Диск | ~40 ГБ свободно | ~55 ГБ |

При нехватке ОЗУ: по 1 ГБ на ВМ (консольной Kali хватает) и модель LLM побыстрее
(`OLLAMA_MODEL=qwen2.5:1.5b` в `.env`, см. DEPLOYMENT.md §7).

## Шаг 1. Установить VirtualBox

1. Скачать: https://www.virtualbox.org/wiki/Downloads → **Windows hosts**
   (платформа x86/AMD64). Extension Pack **не нужен**.
2. Установить со всеми дефолтами. В процессе Windows спросит про установку
   USB/сетевых драйверов — согласиться (создастся адаптер Host-Only).
3. Проверка: Пуск → Oracle VirtualBox открывается; в «Диспетчере устройств» /
   `ipconfig` есть адаптер **VirtualBox Host-Only Ethernet Adapter**
   (IPv4 `192.168.56.1`).

## Шаг 2. Проверить сеть Host-Only (192.168.56.0/24 с DHCP)

1. VirtualBox → **Файл → Инструменты → Менеджер сетей** (Ctrl+Shift+H) →
   вкладка **Сети только для хоста**.
2. Выбрать `VirtualBox Host-Only Ethernet Adapter` (если пусто — кнопка
   **Создать**): вкладка «Адаптер» → IPv4 `192.168.56.1`, маска `255.255.255.0`;
   вкладка **DHCP-сервер** → галочка **Включить** (адреса раздаёт из
   `192.168.56.100–254` — у ВМ будут разные IP автоматически).

> Если адаптер называется иначе (например, `#2`) — запомни имя, оно понадобится
> в шаге 4. Все команды ниже используют `<HOST_IP>` = `192.168.56.1`.

## Шаг 3. Разрешить входящие порты в Windows Firewall

ВМ будут стучаться в хост по TCP **8000** (API), **1514/1515** (агенты Wazuh),
**55000** (Wazuh API). PowerShell **от администратора**, одна команда:

```powershell
New-NetFirewallRule -DisplayName "SIEM stand (VMs)" -Direction Inbound `
  -Protocol TCP -LocalPort 8000,1514,1515,55000 -Action Allow
```

(Либо Windows сам спросит «Разрешить доступ?» при первом старте контейнеров —
но правило выше надёжнее и точечно.)

## Шаг 4. Создать ВМ-1 `mail-prod-01`

1. **Машина → Создать**: Имя `mail-prod-01`; Тип `Linux`; Версия `Debian (64-bit)`.
2. ОЗУ **2048 МБ** (можно 1024 при нехватке), CPU 1–2, диск **VDI, динамический,
   15 ГБ**.
3. **Настройки → Носители** → контроллер SATA/IDE → «Оптический привод» →
   выбрать скачанный ISO (шаг «Скачать Kali» ниже — сначала скачай ISO
   `kali-linux-light-*.iso` со страницы https://www.kali.org/get-kali/
   раздел **Bare Metal / Light**; прямой каталог: https://cdimage.kali.org/ —
   бери текущий `kali-linux-light-<версия>-amd64.iso`, ~3 ГБ).
   Отметить «Live CD/DVD».
4. **Настройки → Сеть**:
   - Адаптер 1: **NAT** (интернет для `apt`) — уже так по умолчанию;
   - Адаптер 2: ✅ Включить → Тип: **Виртуальный адаптер хоста** → имя адаптера
     из шага 2.
5. Прочее не трогать (BIOS, без EFI; дисплей/USB по умолчанию).

Для ВМ-2 повтори пункты с именем **`wks-finance-12`** (и ВМ-3 `app-web-01`,
если нужна). Настроить ВМ можно и потом, клоны тоже подойдут — но проще
сразу создать все и ставить по очереди.

## Шаг 5. Установить Kali (урезанно — только консоль)

Запусти ВМ-1 → загрузчик ISO → **Graphical Install** (это интерфейс УСТАНОВЩИКА,
не системы — графику в самой системе мы не ставим):

1. Язык/страна/раскладка — на твой вкус (можно русский).
2. **Имя компьютера (hostname): `mail-prod-01`** (для ВМ-2 — `wks-finance-12`;
   удобно для чтения логов; имя wazuh-АГЕНТА задаётся отдельно на шаге 7).
   Домен: пусто.
3. Пароль `root`: **оставь пустым** — тогда созданный пользователь получит
   полный sudo (стандарт Debian/Kali).
4. Пользователь: имя `operator`, пароль — запомни его (он нужен для SSH и sudo).
5. Разметка диска: **Авто — использовать весь диск** → весь диск в один раздел
   → «Завершить разметку и записать…» → «Да».
6. **Выбор программ (tasksel) — САМОЕ ВАЖНОЕ ДЛЯ «УРЕЗАННОСТИ»**: сними
   **ВСЕ** галочки — `Xfce` и все наборы (`top10`, `default`, `large`,
   `everything` и т.п.). Оставь только пункт стандартных утилит, если он есть.
   → Получим консольную систему без рабочего стола и без тысяч инструментов
   (дальше ставим только: sshd, nginx, rsyslog, wazuh-agent — всё, что нужно
   тестам, и ничего лишнего).
7. GRUB → устройство `/dev/sda`. Перезагрузка. ISO отмонтируется сам
   (иначе: Настройки → Носители → убрать ISO).

ВМ-2 (и ВМ-3) — то же самое со своим hostname.

## Шаг 6. Поднять вторую сеть на ВМ (host-only)

После первого входа `operator@mail-prod-01` в консоли ВМ:

```bash
sudo apt update && sudo apt install -y curl ca-certificates   # минимум
ip -br a        # найди интерфейс БЕЗ адреса (обычно enp0s8) — это host-only
```

Подключить его (имя интерфейса подставь своё):

```bash
echo 'allow-hotplug enp0s8
iface enp0s8 inet dhcp' | sudo tee -a /etc/network/interfaces
sudo ifup enp0s8
ip -br a        # теперь у второго интерфейса есть 192.168.56.x
```

**Контрольная точка 1** (стенд Docker должен быть запущен:
`docker compose up -d` на хосте):

```bash
ip -br a                                   # 192.168.56.x на втором интерфейсе
curl http://192.168.56.1:8000/api/v1/health   # {"status":"ok",...}
```

Если `curl` не проходит — вернись к шагу 3 (firewall) и проверь, что стенд
запущен (`docker compose ps`).

**Удобство**: дальше работай по SSH с Windows-терминала, а не в окне ВМ
(консоль оставь на случай поломки сети):

```powershell
ssh operator@192.168.56.101    # IP см. в ip -br a ВМ-1
```

## Шаг 7. Подготовить узлы и поставить wazuh-агентов

Ровно по [E2E_STAND.md](E2E_STAND.md) — короткая выжимка:

**ВМ-1 (сервер):**

```bash
sudo apt install -y openssh-server nginx rsyslog
sudo systemctl enable --now ssh nginx rsyslog
sudo useradd -m -s /bin/bash admin && sudo passwd admin   # жертва для брутфорса
ls -l /var/log/auth.log   # лог должен существовать
```

**Обе ВМ — агент 4.7.4** (репозиторий + установка; **имя агента = имя актива**,
по нему SIEM привязывает события и находит цель реакций):

```bash
curl -s https://packages.wazuh.com/key/GPG-KEY-WAZUH \
  | gpg --dearmor | sudo tee /usr/share/keyrings/wazuh.gpg > /dev/null
echo "deb [signed-by=/usr/share/keyrings/wazuh.gpg] https://packages.wazuh.com/4.x/apt/ stable main" \
  | sudo tee /etc/apt/sources.list.d/wazuh.list
sudo apt update
# ВМ-1:
WAZUH_MANAGER="192.168.56.1" WAZUH_AGENT_NAME="mail-prod-01" sudo apt install -y wazuh-agent
# ВМ-2:
WAZUH_MANAGER="192.168.56.1" WAZUH_AGENT_NAME="wks-finance-12" sudo apt install -y wazuh-agent
sudo systemctl daemon-reload && sudo systemctl enable --now wazuh-agent
```

На ВМ-1 добавь локалфайл nginx в `/var/ossec/etc/ossec.conf` (перед
`</ossec_config>`) и перезапусти агента:

```xml
<localfile>
  <log_format>apache</log_format>
  <location>/var/log/nginx/access.log</location>
</localfile>
```

**Обе ВМ — AR-скрипты** (менеджер их не рассылает; с Windows-хоста, из каталога
репозитория):

```powershell
scp wazuh/ar/*.sh operator@192.168.56.101:/tmp/
scp wazuh/ar/*.sh operator@192.168.56.102:/tmp/
```

на каждой ВМ:

```bash
sudo install -m 750 /tmp/block-ip.sh /tmp/lock-account.sh /tmp/isolate-host.sh \
  /var/ossec/active-response/bin/
```

**Контрольная точка 2** (на хосте):

```bash
docker compose exec wazuh-manager bash /wazuh-config/setup.sh   # один раз (и после recreate)
docker compose exec wazuh-manager /var/ossec/bin/agent_control -l
#   mail-prod-01    ... Active
#   wks-finance-12  ... Active
```

## Шаг 8. Снимок «стенд готов» — и практика снапшотов

В VirtualBox: выбери ВМ → меню ☰ (или Machine) → **Снимки → Сделать**.
Назови `stand-ready`. Повтори для каждой ВМ.

Как это защищает тестирование:

- **Откат мгновенен**: если реакция или сценарий сломали узел (забытая
  блокировка, изоляция) — правый клик по снимку → **Восстановить**, и ВМ снова
  чистая за секунды (вместо ручной чистки iptables/учёток).
- Перед каждым прогоном сценария можно снять `pre-scenario-N` и после успеха
  откатиться.
- Снимки занимают место на диске только за дельту — можно не экономить.

## Изоляция (почему стенд не мешает остальному)

- **Host-only (192.168.56.0/24)** — закрытая сеть: видят только хост и ВМ
  стенда; из интернета и локальной сети организации к ВМ не попасть.
- **NAT на ВМ** — только ИСХОДЯЩИЙ интернет (для `apt`): входящие извне
  невозможны.
- Атаки из сценариев идут **только на адреса 192.168.56.x** — внимательно с
  `hydra`/`nmap`: цель всегда `<IP_ВМ-1>` (192.168.56.101-ish).
- Реакции меняют состояние ВМ, не хоста: `iptables`/`passwd` выполняются
  внутри Kali.
- Docker-стенд на хосте живёт как раньше; ВМ добавляют только 1514/1515/55000
  (порт Wazuh) и трафик к 8000.

## Типичные проблемы установки

| Симптом | Решение |
|---|---|
| ВМ не видит 192.168.56.x на втором интерфейсе | Не сделан `ifup` (шаг 6); неверное имя интерфейса (`ip -br a`); DHCP выключен в Менеджере сетей (шаг 2) |
| `curl http://192.168.56.1:8000/...` таймаутится | Windows Firewall (шаг 3); стенд не запущен (`docker compose ps`) |
| Агент не появляется в `agent_control -l` | Порт 1515 закрыт файрволом (шаг 3); в конфиге агента неверный `WAZUH_MANAGER` (переставить пакет с верной переменной) |
| `apt update` на ВМ не работает | NAT-адаптер выключен/нет интернета на хосте; `sudo dhclient <NAT-интерфейс>` |
| Kali грузится в графику | В шаге 5.6 tasksel: были отмечены Xfce — можно жить и так, либо переустановить с чистого снимка |
