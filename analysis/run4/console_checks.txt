Сценарий С1-бис «Компрометация учётной записи после подбора пароля» — протокол (2026-11-18)
Цель: демо TP-вердикта LLM на доказательствах успешного входа + демонстрация новых фич
(стабильность тактики, статусы OPEN/IN PROGRESS/CLOSED, Summary при закрытии).

Подготовка:
- Новое правило Wazuh 100110 (if_sid 5715, groups[0]=authentication_success, level 8) —
  verified wazuh-logtest; правило корреляции БД brute_force_succeeded (min 1,
  credential_access) — по умолчанию выключено, активируется только на время прогона
  (иначе каждый легитимный SSH-вход создавал бы инцидент).
- После force-recreate wazuh-manager ОБЯЗАТЕЛЕН setup.sh (bash /wazuh-config/setup.sh) —
  без него интегратор не доставляет алерты в SIEM (алерты только в alerts.json).
- Автоматизация пароля с хоста: OpenSSH SSH_ASKPASS_REQUIRE=force + askpass-скрипты.

Грабли:
- MSYS path mangling: docker exec пути (/wazuh-config-mount/...) и -v монтирования —
  MSYS_NO_PATHCONV=1 или двойные слеши.
- -b 192.168.56.50 работает только на ХОСТЕ (алиас на адаптере); из контейнера — bind fail.
- Задержка доставки агента (~секунды): правило корреляции активировать ДО успешного
  входа и деактивировать ПОСЛЕ появления события в SIEM (первый прогон: правило
  выключили раньше — success-событие не приклеилось).
- Локаторы playwright на этой странице нестабильны — координатные клики надёжнее.
